网站直连检测工具 sitecheck  v2.0
================================================

无需安装 Python，整个 sitecheck 文件夹拷到任意 Windows 机器上即可使用。
双击无黑框，同时提供图形界面和命令行两种用法。


【启动】

    双击：sitecheck\sitecheck.exe        -> 打开图形界面
    分发：把 sitecheck 整个文件夹一起拷贝（或压成 zip），
          不要只拷里面的 exe，依赖在 _internal 目录里


【图形界面】

    ┌──────────────────────────────────────────────────────┐
    │ 网站直连检测                                   v2.0  │
    ├──────────────────────────────────────────────────────┤
    │ [ 单站检测 ] [ 批量检测 ]                            │
    │                                                      │
    │  域名      [ github.com                          ]   │
    │  指定 IP   [ 可选，多个用逗号分隔                 ]   │
    │  [开始检测] [写入 hosts] [导出报告] [清空]           │
    │                                                      │
    │  真实 IP：140.82.114.4、20.205.243.166      [+]      │
    │  可以直连（HTTP 200） | 阻断点：可直连                │
    │  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓                │
    │  ┌─ 检测日志 ──────┬─ 检测结果 ──────────────┐      │
    │  │ [DNS 解析] 1/9  │ 结论 + 依据 + 建议       │      │
    │  │ [逐 IP 探测] 2/6│ DNS 表 / 逐 IP 探测表    │      │
    │  └─────────────────┴──────────────────────────┘      │
    └──────────────────────────────────────────────────────┘

  · 窗口可缩放、可最大化（v1.0 是固定尺寸）
  · 输入框回车 = 开始检测；检测在后台线程跑，界面不卡
  · 进度条是确定的，日志区保留每一步的耗时
  · 「+」按钮：把检测出的真实 IP 追加进「指定 IP」栏
  · 「导出报告」支持 Markdown / JSON / HTML 三种格式
  · 「写入 hosts」只在真的需要写时才亮起：
        · DNS 不可用但找到可直连的真实 IP   -> 可用
        · DNS 本身正常                      -> 禁用（没必要）
        · hosts 里已有该条目且可用           -> 禁用（保持现状）
    点击后先弹确认框展示改动预演，确认后自动备份、写入、刷新缓存。
    需要管理员权限，会弹 UAC。

  · 批量检测标签页：一次输入多个域名（每行一个，或用逗号/空格分隔），
    结果表格展示 域名 / 结论 / 阻断点 / 真实 IP / HTTP / 耗时，可导出 CSV。


【命令行：带参数运行】

按 Win+R 输入 cmd 回车，cd 到 exe 所在目录：

    sitecheck.exe github.com
    sitecheck.exe github.com --ip 93.184.216.34
    sitecheck.exe github.com --report out.md
    sitecheck.exe github.com --json out.json --html out.html
    sitecheck.exe github.com --apply-hosts

    sitecheck.exe hosts                     列出 hosts 条目
    sitecheck.exe hosts --audit             体检：逐条探测是否真的可用
    sitecheck.exe hosts --backups           列出备份
    sitecheck.exe hosts --restore           还原最新备份
    sitecheck.exe hosts --restore 1         还原第 1 个（0 是最新）

    sitecheck.exe dns-bench                 公共 DNS 延迟 / 防污染基准测试
    sitecheck.exe --version

  注意：打包为无控制台程序后，`sitecheck.exe x > out.txt` 的重定向会失效
  （cmd 不等待窗口程序结束）。需要重定向时请用 --report / --json 参数，
  或用 `python -m sitecheck.cli` 运行。


【它告诉你什么】

1. 网站的真实 IP —— 判定依据是 TLS 证书 SAN 匹配，不是 DNS 说什么。
   DNS 被污染成别家 IP 时，它会如实报"未能确认"，不会把假 IP 当真的给你。

2. 能不能直连。

3. 不能连的话卡在哪一层：

   阻断点              含义                              改 hosts 有用吗
   -----------------------------------------------------------------------
   DNS                 域名解析不出记录                  不适用
   TCP                 服务器 443 端口连不上             无效
   TLS/SNI             TCP 能连但握手被切断              无效（够不到这一层）
   DNS 污染            解析到的 IP 上不是你要访问的站    有效（前提是找到真 IP）
   HTTP_NO_RESPONSE    证书正常但 HTTP 层没响应          无效，查代理/防火墙
   HTTP_REJECT         拿到 4xx/5xx，链路是通的          无效，问题在服务端策略
   PROXY_REQUIRED      直连不通，但经代理可访问          无效，是本机代理配置
   INCONCLUSIVE        控制组也不通，本机出网受限        先修网络

4. 能不能靠改 hosts 解决。
   只有「DNS 给的 IP 全不通，但存在证书匹配且能正常响应的其他 IP」
   时才建议改，并直接给出可粘贴的条目。
   DNS 本身正常时不会误导你去改 hosts。

5. 能连的话给优化建议（DNS 延迟对比、HTTP/2、TLS 版本、证书到期、
   跳转、首字节耗时）。

每条结论都附带「依据」，说明为什么这么判，而不是只丢一个结论。


【看结果时注意】

报告开头有「控制组」一栏。控制组是几个不同运营商的站点，
如果它们全部不通，说明本机出网受限 —— 此时工具会直接判
INCONCLUSIVE，而不是把责任推给目标站点。

本工具发的是极简请求头，服务端返回 403/429 之类多半是反爬、
地域限制或 WAF —— 不代表浏览器打不开。
但请注意：如果一个字节都没收到（HTTP_NO_RESPONSE），
那就不是反爬，是链路问题，这两件事的处理方式完全不同。

如果本机配置了代理，工具会同时报告直连和经代理两条路径的结果。
直连不通、经代理可通时，说明问题在本机代理配置，不要改 hosts。


【关于 hosts】

写入前会自动备份到：
    %LOCALAPPDATA%\sitecheck\backups\hosts-<时间戳>.bak
保留最近 10 份，可用 `sitecheck hosts --restore` 一键回滚。

写入按原文件编码写回，并采用临时文件 + 原子替换，
中途失败不会留下半截 hosts。


【体积与启动】

目录约 100 MB（内含 Qt 界面运行时），启动约 0.5~1 秒。
单次检测耗时取决于网络：能直连的站点通常 2~4 秒；
站点被黑洞（TCP 通但 HTTP 一个字节都不回）时最坏约 16 秒 ——
这段等待是必要的，用来区分"服务端慢"和"链路被切断"。


【其他】

- 除「写入 hosts」外，工具本身是只读的：不修改 hosts、不改 DNS、
  不改任何系统配置
- 重新打包：python build.py（onedir，默认）
